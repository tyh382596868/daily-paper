### 1. AR-VLA: True Autoregressive Action Expert for Vision-Language-Action Models
- **作者**: Hu Yutong, Zaech Jan-Nico, Nikolov Nikolay, Yao Yuanqi, Dey Sombit, Albanese Giuliano, Detry Renaud, Van Gool Luc, Paudel Danda
- **机构**: 未知（abs 页面 affiliations 未拿到）
- **链接**: [arXiv](https://arxiv.org/abs/2603.10126) | [PDF](https://arxiv.org/pdf/2603.10126)
- **来源**: 📰 HF Daily，⬆️ 0
- 📒 **笔记**: [[AR-VLA]]

![](https://arxiv.org/html/2603.10126v2/x1.png)

- **核心方法**: 输入是视觉 + 语言 prefix，输出是一段连续的动作序列。关键改动：抛弃传统 VLA 的 chunk-then-reset 范式，让 Action Expert 维护一条**长时 KV 记忆**，沿时间方向连续生成动作；用一个 **re-anchoring 机制**显式处理 perception staleness（即 vision 更新慢、控制更新快的频率失配）。其设计哲学是把感知和控制解耦预训练、模块化拼接，因此可以挂在不同的重型 [[VLM]] backbone 上做 generalist 或 specialist 策略。
- **对比方法/Baselines**: 对比 [[OpenVLA]] / [[PaliGemma]] / [[FAST]] 这一系列 chunk-based 动作头；评测套件包括 [[PushT2]]、[[BridgeV2]]、[[WidowX]]、[[ALOHA]]、[[SimplerEnv]] 等真实/仿真平台。
- **借鉴意义**: 如果你在做 [[VLA]] 或者 [[Diffusion Policy]]，这篇直接攻击的是「reactive、context-less」这个长期被忽视的范式问题。Action Expert 这种"动作侧自己有记忆"的思路，可能比再往 vision encoder 里塞 history 更优雅。
- **锐评**: 这是一篇真正在动 VLA 范式而不是堆架构的论文。"动作侧自带历史 + perception 延迟显式建模" 这个 framing 比一堆 "我加了 attention/我换了 backbone" 的文章强太多。已经在 real-robot 上验证（has_real_world=true）。唯一让人警惕的是 abstract 把 smoothness 说得很满，但具体 success rate 对比没有透出来，需要看正文表格判断到底是「smooth 但不强」还是「smooth 且强」。🔥
- **关联笔记**: [[VLA]]、[[3-机器人策略]] 这条线下的 [[ActionChunking]] 直接被这篇挑战；[[OpenVLA]] 是主要对比对象。

### 2. OxyGen: Unified KV Cache Management for VLA Inference under Multi-Task Parallelism
- **作者**: 完整作者列表见原文
- **机构**: Department of Electronic Engineering, Tsinghua University
- **链接**: [arXiv](https://arxiv.org/abs/2603.14371) | [PDF](https://arxiv.org/pdf/2603.14371)
- **来源**: 📄 arXiv 关键词检索

![](https://arxiv.org/html/2603.14371v2/x1.png)

- **核心方法**: 针对 [[MoT]]（Mixture-of-Transformers）VLA（比如 π0.5）做推理优化：把 KV cache 从「每个任务独立」改造成「跨任务共享的一等资源」。两个核心 trick：(1) **cross-task KV sharing** 消除共享观察的重复 prefill；(2) **cross-frame continuous batching** 把变长语言解码和定速动作生成解耦。在 RTX 4090 和 Jetson AGX Thor 上跑 [[LIBERO]] 验证。
- **对比方法/Baselines**: 主要基线是 [[π0.5]] 默认推理路径；架构假设建立在 MoT VLA 上。
- **借鉴意义**: 不在乎推理工程的可以跳，但如果你在做**端侧 VLA 部署**或**多任务并行控制**，这个 KV 设计是直接可用的工程模板。
- **锐评**: 标准的系统优化论文，故事讲得清楚——「现有系统在 MoT VLA 上 cache 管理是浪费」这个 framing 是对的。但严格说没有方法层面的新东西，本质上是把 LLM serving 里成熟的 KV 共享思路搬到 VLA。对学界帮助有限，对工业部署很有价值。👀
- **关联笔记**: [[VLA]]、[[π0]] 系列（[[LeWM]] 同走 π0.5 路线）

### 5. Global Prior Meets Local Consistency: Dual-Memory Augmented Vision-Language-Action Model (OptimusVLA)
- **作者**: 完整作者列表见原文
- **机构**: Harbin Institute of Technology, Shenzhen Loop Area Institute, Huawei Noah's Ark Lab
- **链接**: [arXiv](https://arxiv.org/abs/2602.20200) | [PDF](https://arxiv.org/pdf/2602.20200)
- **来源**: 📄 arXiv 关键词检索

![](https://arxiv.org/html/2602.20200v2/x1.png)

- **核心方法**: 解决层级 VLA 的两个痛点：denoising 步数多、缺乏时序一致性。设计了双记忆：**Global Prior Memory (GPM)** 从语义相似 trajectory 检索 task-level prior 替代 Gaussian noise，缩短生成路径降低 NFE；**Local Consistency Memory (LCM)** 动态编码已执行 action sequence 推断任务进度。最终 flow policy 用自适应 NFE 调度生成 action chunk。
- **对比方法/Baselines**: 对比标准 flow-based VLA；在 [[LIBERO]] 和真实机器人上验证。
- **借鉴意义**: 「检索 prior 替代 Gaussian noise」这个思路在 [[Diffusion Policy]] 圈很有市场，比单纯堆 denoising step 优化要可解释得多。
- **锐评**: 双记忆 + retrieval prior 的组合不算原创——做 image generation 的人玩了很久了——但搬到 VLA 上是有价值的工程探索。两个 memory 听起来像在凑 contribution，需要看 ablation 是不是真两个都不可或缺。👀
- **关联笔记**: [[VLA]]、[[RLA-WM]]（也涉及 prior + VLA）

### 17. FASTER: Rethinking Real-Time Flow VLAs
- **作者**: 完整作者列表见原文
- **机构**: The University of Hong Kong, ACE Robotics
- **链接**: [arXiv](https://arxiv.org/abs/2603.19199) | [PDF](https://arxiv.org/pdf/2603.19199)
- **来源**: 📄 arXiv 关键词检索
- 📒 **笔记**: [[FASTER]]

![](https://arxiv.org/html/2603.19199v3/x1.png)

- **锐评**: 这是一篇有 punch line 的论文，故事干净有力。「flow VLA 反应延迟 10×」如果数据扎实就是直接可部署的优化。质疑点：「近端 1 步去噪」会不会牺牲一些边界场景的动作精度？需要看长 horizon 任务上是否真的没退化。has_real_world=true。🔥

## 趋势判断

VLA 不再"造新架构"了——这一周看到的所有 VLA 论文都在解 *operational* 痛点：反应延迟（FASTER）、KV 复用（OxyGen）、记忆持久化（RoboMME / UAM）、动作 commit 策略（A3）、token 表示（GridS）。这是技术成熟的信号，但也意味着真正的"下一代 VLA 范式"机会窗口在打开。World model 这边，**「JEPA 系做系统 ablation」**（#11）和 **「WM = 可微物理引擎」**（#7）是两条不同的进化路径，今年值得追踪谁会跑出来。还有一个被低估的信号：**3DGS 正在悄悄变成 sim-to-real 的事实基础设施**（GRaD-Nav++、PanoWorld），这是 [[3D Gaussian Splatting]] 笔记应该重点扩展的方向。
