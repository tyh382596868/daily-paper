# 非对称注意力掩码

## 定义

Transformer 中按 token 类别设计的不对称可见性矩阵：不同类别的 token 可见范围不同，常用于在不破坏预训练 backbone 的前提下"附加"新功能模块。

## 数学形式

掩码 $M_{ij} \in \{0, -\infty\}$ 不再要求对称（$M_{ij} \ne M_{ji}$）。注意力计算：

$$
\mathrm{Attn}(Q, K, V) = \mathrm{softmax}\!\left(\frac{Q K^\top}{\sqrt{d_k}} + M\right) V
$$

例子（[[EvoScene-VLA]] 的 VLM 前缀）：

| 查询 \ 键 | image | language | obs slots | prior slots |
|---|---|---|---|---|
| image | ✓ | ✓ | × | × |
| language | ✓ | ✓ | × | × |
| obs slots | ✓（自视角） | ✓ | × | × |
| prior slots | × | × | ✓ | × |

## 核心要点

1. **保护预训练通路**: 让原本的 image/language 通路看不到新加的 token，避免污染预训练表示
2. **形成信息瓶颈**: 通过限制可见性强制信息按特定路径流动（图像 → obs → prior）
3. **vs. 对称掩码**: 标准 causal 或 bidirectional 掩码 $M_{ij}=M_{ji}$；非对称下两侧可独立设计
4. **vs. [[chunk-causal]]**: chunk-causal 是按时间块的对称掩码，本概念是按 token 类别的不对称掩码
5. **典型应用**: VLM 加新功能 token、prefix tuning、recurrent state token

## 代表工作

- [[EvoScene-VLA]]: 在 VLM 前缀里给观测槽 / 先验槽设计不对称掩码，保护 Qwen2.5-VL 预训练通路
- 多数 prefix-tuning / adapter 类工作隐含使用该模式
